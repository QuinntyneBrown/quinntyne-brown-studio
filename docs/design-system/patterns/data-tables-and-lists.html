Data tables and lists

Density, sorting, filtering, selection and the responsive strategy for admin data.

WCAG 2.2 AAPattern

  • Structure
  • States
  • Responsive behaviour

Overview

Admin works through sessions, photographers, equipment, vendors, rates, promotions and inquiries. They all share one table recipe: toolbar above, table in a scrolling wrapper, pagination below.

When to use

  • Table for comparing several attributes across many items.
  • Cards (card, photo tile) for visual items such as photographs.
  • Description list for one record's details.
  • Calendar for schedules.

Structure

Toolbar with search and filter, then the table.

States

  • Loading: skeleton rows with the real column count.
  • Empty: empty state inside the table area; filtered-empty offers Clear filters.
  • Error: alert with retry above the table.
  • Selected: row background --color-accent-subtle and a selection bar showing the count and bulk actions.
  • Sorted: aria-sort on the active header with an arrow.

Responsive behaviour

  • Below 768px the table scrolls inside its wrapper; the first column stays readable and actions remain reachable.
  • Toolbars wrap: search takes a full row, filters and the primary action follow.
  • Prefer fewer columns on phones by hiding secondary columns with a documented data-priority rule rather than truncating.

Accessibility

  • Real <table> with <caption> and scope; icon-only action columns have a visually hidden heading.
  • Sort buttons live in header cells and expose aria-sort.
  • Row actions are buttons reachable by Tab; never rely on row hover.
  • Selection checkboxes are labelled with the row name; announce "3 selected" in a live region.

Content

  • Column headings are short nouns in the eyebrow style.
  • Dates and money format as in content; align numerals right with tabular figures.
  • Empty cells show an en dash with visually hidden "none".
