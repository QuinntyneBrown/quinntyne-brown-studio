Pattern

Empty and error states

Copy formulas and layouts for when there is nothing to show or something went wrong.

WCAG 2.2 AAPattern

  • Structure

Overview

An empty or failed screen is still a screen. It should say why, offer one way forward, and keep the shell so people can navigate away.

When to use

CaseComponentExample
First runEmpty stateNo galleries yet. Assign a session gallery to a client.
No results for filtersCompact empty stateNo sessions match these filters. [Clear filters]
No permissionError page 403You don't have access to this page.
Not foundError page 404We couldn't find that page.
Service failureError page 500 with referenceSomething went wrong on our side. Reference QB-7F3A.
Session expiredError page + sign inYour session expired. Sign in again to continue.

Structure

Empty list and failed load, inside the normal page chrome.

•

No sessions match

Try a different date range or photographer.

Title, one sentence, one action.

Couldn't load sessions. Your data is safe. Check your connection and try again.

A failed load keeps the page and offers retry.

States

  • Loading precedes empty: never flash an empty state while data is loading.
  • Error replaces content only if nothing can be shown; otherwise keep stale content and show an alert.
  • Offline and slow-network variants reuse the alert with a retry.

Responsive behaviour

  • Empty states centre in the available width with a 27rem text cap.
  • Error pages keep the narrow single column at every width and the primary action is full width on phones.

Accessibility

  • Error pages set the document title and the single <h1> to the problem.
  • Focus moves to the heading after a client-side route change to an error view.
  • Recovery actions are real buttons or links, never text-only instructions.
  • Do not convey the error with an icon or colour alone.

Content

  • Formula: what happened, what it means for them, one next step.
  • Never blame the person; never expose stack traces or codes without a plain sentence.
  • Include a reference id on 500 errors so support can find it.
