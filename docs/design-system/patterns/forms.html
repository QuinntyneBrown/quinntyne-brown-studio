Forms

Layout, validation timing, error summary and submit states for every form in the studio apps.

Overview

Forms are where clients and staff do the real work: requesting a quote, creating a session, uploading photos, submitting a print request. This pattern fixes how fields are laid out, when they validate, and how errors surface.

When to use

  • Use a single column for every form below 768px and for short forms always.
  • Use two columns only for editors with many short, related fields (session editor).
  • Group fields in .form-sections with a serif heading when a form has more than seven fields.
  • Use a dialog only for forms of one to three fields.

Structure

Error state shown. Labels sit above controls, hints below, one primary action last.

States

VariantDefaultInvalidRead-onlyDisabled
Text field
  • Validate on blur, then re-validate on every input once a field has errored. Never validate an empty field the person has not left.
  • On submit validate everything, show the error summary, move focus to it and keep every entered value.
  • Submitting: the primary button shows its busy state; the form stays editable only if the server supports it, otherwise fields become read-only.
  • Server failure: show an alert above the actions with a retry; never clear the draft.

Responsive behaviour

  • Single column below 768px; the primary action becomes full width and sits last.
  • The summary stays above the fields; fields keep 44px height on touch.
  • Two-column forms align labels above controls at every width.

Accessibility

  • Every control has a programmatic label (for/id); placeholders are hints only (3.3.2).
  • Errors: aria-invalid="true" and aria-describedby pointing at the message; the summary is role="alert" with focus moved to it (3.3.1, 3.3.3).
  • Use autocomplete on name, email, phone and address fields (1.3.5).
  • Required fields say "required" in the label text, not by colour or asterisk alone.
  • Changing a select never submits or navigates (3.2.2). Never block paste (3.3.8).

Content

  • Labels are nouns ("Session date"), sentence case. Hints say why, not what.
  • Error formula: what is wrong + how to fix it. "Choose a date at least two days from now."
  • Primary button names the outcome: "Send request", "Save session".
