Content and tone

How the studio writes: voice, button verbs, numbers, error and empty-state copy.

Overview

This pattern applies the content foundation to real screens. The goal is copy a client can act on without reading twice.

When to use

  • Write every string as the real string; do not ship lorem ipsum or developer wording.
  • Review copy with the same rigour as visuals: it is part of the component.
  • Escalate new message types to the formulas table before inventing a style.

Structure

The same moment, written badly and well.

Error: Request failed (422).

We couldn't send your request. Nothing was lost. Check the highlighted fields and try again.

Left: avoid. Right: use.

States

  • Loading text names the thing: "Loading galleries…".
  • Success is past tense; failure says what is safe; empty explains and offers one action.
  • Confirmation repeats the verb and object.

Responsive behaviour

  • Short labels: a button label that wraps at 390px is too long.
  • Truncate nothing that carries meaning; wrap instead.

Accessibility

  • Plain language; expand abbreviations on first use.
  • Link text is meaningful alone (2.4.4).
  • Alt text describes what the photograph shows and why it is there, in one sentence (1.1.1).
  • Mark language changes with lang (3.1.2).

Content

  • Sentence case, no all-caps typing, minimal punctuation.
  • Money in CAD with the estimate caveat; dates unambiguous; times with zone.
  • Names of things match the nav: Sessions, Galleries, Albums, Print requests.
