Foundations

ColorWarm neutrals, a muted olive and three status hues, remapped per theme so components never change. TypographyGeorgia headings, Arial body, nine sizes and twelve role shorthands. SpacingA 4px scale from 0 to 96px with rules for inside and between. LayoutBreakpoints, a 4/8/12 column grid, shell dimensions and page templates. ElevationFour shadow levels, surface hierarchy and a nine-layer z-order. ShapeFive radii and two border widths. MotionFive durations, four easings, reduced-motion by default. IconographyA 24-unit stroke icon set that inherits text colour. ThemingThree token tiers, light and dark themes, and how to add another. ResponsiveMobile-first rules and what each component does at 390, 768 and 1440 px. AccessibilityThe WCAG 2.2 AA commitments the system makes and how they are tested. ContentVoice, casing, numbers and the message formulas for errors, empty states and confirmations.

Components

Actions

ButtonButtons let people take an action: save, send, delete, open. Button groupA button group keeps related buttons together as one unit, either as a row of peer actions or as a segmented control that switches a view. LinkA link takes the person somewhere else: another page, a section, a file or another site. MenuA menu gathers a short list of actions behind one trigger, so a row or header can offer several choices without showing them all.

Inputs

CheckboxA checkbox records a yes-or-no choice, or lets a person pick any number of options from a short list. Date navigatorThe date navigator steps through time one period at a time, so a person can move between weeks or months on a schedule without opening a calendar. File uploadFile upload lets a person add files by choosing them or dropping them, then shows each file’s progress so they know what arrived. Form fieldThe form field is the wrapper every input sits in. Form layoutForm layout arranges fields into sections, columns and an action bar, and gathers every error into a summary the person can act on. Radio groupA radio group presents two to six options and lets the person choose exactly one, with every option visible. SelectA select lets a person choose one option from a list of about five to fifteen, using the browser’s own picker. SwitchA switch turns one setting on or off, and the change takes effect straight away without a save step. Text fieldA text field takes a single line of text: a name, an email address, a password, a price or a search term. TextareaA textarea takes free text longer than a line: a message to the studio, session notes, a caption or a print request comment.

Navigation

BreadcrumbA breadcrumb shows where this page sits in the hierarchy and gives a one-click way back up. FooterThe footer closes every public page with the brand, a short list of secondary links and the copyright line. PaginationPagination splits a long list into pages and lets people step through them or jump to one. SidebarThe sidebar is the admin workspace's table of contents: every area of the studio, grouped, with the current one marked. Skip linkA skip link is the first thing a keyboard user can reach on every page. TabsTabs switch between sibling views of the same thing without leaving the page. Top barThe top bar names the product and gives the way to every top-level destination.

Containers and overlays

AccordionAn accordion stacks short headings that each reveal a block of content. CardA card groups the information and actions about one thing, such as a session, an album or a print request, on a bordered surface. DialogA dialog interrupts the page to ask one thing or show one thing. DividerA divider is a thin rule that separates two groups of content. Layout primitivesFive small classes arrange everything on a page: container, grid, stack, cluster and split. TooltipA tooltip names or briefly explains a control when it is hovered or focused.

Data display

AvatarAn avatar is a small round mark that stands for a person: a photographer, a client, the signed-in user. BadgeA badge is a short status label: Scheduled, Delivered, Ready for review. Blog cardA blog card is a single article in a listing: image, date, title and a two-line abstract, all one link to the post. ChipA chip is a compact token for a filter, a selection or a tag. Cost summaryThe cost summary lists what a quote or print order costs, line by line, and ends with one total. Description listA description list pairs short labels with values for one record: an inquiry, a session, a studio. Line itemA line item is one product in a request or order: a photograph, its print size, a quantity field and the line price. Photo tileA photo tile is one photograph in a grid: a 4:5 crop with a select checkbox, a position label and an optional status badge. Schedule calendarThe schedule calendar shows a week of sessions at a glance: seven day columns, each with its date and its appointments. Selection barThe selection bar sits above a photo grid or table and shows how many items are selected, with the actions that apply to the selection. StatA stat puts one number in front of people with a label and a line of context: sessions this month, photos awaiting review, quotes sent. StepperA stepper shows the steps of a process in order and where the person is in it: the quote journey, a print request, how a session works. TableTables compare records across the same attributes: sessions, print prices, inquiries.

Feedback

AlertAn alert is a message that stays on the page until the situation changes: a failed upload, a pending review, a service problem. Empty stateAn empty state fills the space where content would be, says why it is empty, and offers the next step. Error pageAn error page replaces a whole screen when the page cannot be shown: not found, access denied, service unavailable, session expired. Inline messageAn inline message is the line of text under a field that says how to fill it in, what went wrong, or that it worked. ProgressA progress bar shows how far a process has got: photographs uploading, a print request sending. SkeletonA skeleton is a grey placeholder in the shape of the content that is loading. SpinnerA spinner says the system is working on something short and unmeasurable: loading a gallery, saving a session. ToastA toast confirms something the person just did without taking them out of the task: photographs added, selection saved, changes discarded.

How to use

  1. Link the tokens, then the component stylesheet: tokens/tokens.css, assets/components.css.
  2. Use the documented class names and attributes; do not write raw colours, font stacks or pixel gaps. Reference var(--token).
  3. Set data-theme="dark" on <html> to force dark; otherwise the OS preference applies.
  4. Engineering can generate platform constants from tokens/tokens.json (DTCG).
  5. Check changes with check_contrast.py and check_design_system.py before committing.

Angular components in frontend/projects/components mirror these classes; this site is the specification.
