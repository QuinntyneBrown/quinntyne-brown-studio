Accessibility

The WCAG 2.2 AA commitments the system makes and how they are tested.

WCAG 2.2 AAStatus: stable

Overview

The system targets WCAG 2.2 level AA. These are its commitments; every component page's Accessibility section answers them, and the checker scripts enforce the mechanical parts.

Perceivable

  • Text contrast 4.5:1, large text and control edges 3:1 (1.4.3, 1.4.11), verified for both themes by check_contrast.py.
  • Status is colour plus icon plus text (1.4.1); links are underlined or bordered.
  • Reflow to 320px and 200% text (1.4.4, 1.4.10); text-spacing overrides do not break layouts (1.4.12).
  • Informative images have alt; decorative SVG is aria-hidden; icon-only controls have aria-label (1.1.1).
  • Animation respects prefers-reduced-motion (2.3.3).

Operable

  • Everything works from the keyboard; no traps except modal dialogs, which release on Esc (2.1.1, 2.1.2).
  • One focus ring: 2px --color-focus-ring with 2px offset on :focus-visible, at least 3:1 (2.4.7).
  • Focus is not hidden by sticky bars or toasts (2.4.11).
  • Targets are at least 24px, 44px for primary mobile actions (2.5.8).
  • A skip link to #main opens every page; landmarks are header, nav, main, footer (2.4.1).
  • Auto-dismissing toasts last 8s or more, pause on hover and focus; errors never dismiss themselves (2.2.1).

Understandable

  • Every control has a visible label; placeholders are hints (3.3.2).
  • Errors name the field and the fix; aria-invalid plus aria-describedby; an error summary links each error (3.3.1, 3.3.3).
  • Destructive actions are confirmed or undoable (3.3.4).
  • Changing a select or checkbox never navigates or submits by itself (3.2.2).
  • Password managers and paste are never blocked; sign-in does not require a cognitive test (3.3.8).

Robust

  • Native elements first; ARIA only to fill gaps, following the WAI-ARIA Authoring Practices pattern named on each component page (4.1.2).
  • Status messages use role="status"; errors use role="alert" (4.1.3).
  • Valid HTML: unique ids, no block inside button, no interactive inside interactive.

Testing procedure

  • Run check_contrast.py and check_design_system.py.
  • Tab through the page: order matches visual order and the ring is always visible.
  • Operate every widget with its documented keys.
  • Test with a screen reader (VoiceOver + Safari, NVDA + Chrome) for names, roles and live regions.
  • Zoom to 200% and 320px; enable reduced motion and forced colours.
