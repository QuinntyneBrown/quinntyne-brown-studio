Responsive

Mobile-first rules and what each component does at 390, 768 and 1440 px.

WCAG 2.2 AAStatus: stable
  • Overview
  • Component behaviour by breakpoint
  • Touch
  • Rules
  • Testing matrix

Overview

Mobile first: base styles are the 390px layout and media queries add columns. Browser acceptance runs in Chromium at 390, 768 and 1440 CSS pixels.

Touch

  • Primary controls are 44px or larger (--target-comfortable); nothing is smaller than 24px (--target-min).
  • Hover is an enhancement: every hover effect has a non-hover equivalent.
  • touch-action: manipulation removes the double-tap delay on buttons and inputs.

Rules

  • No horizontal page scroll at 320px; only tables and the calendar scroll inside their wrapper.
  • Images use aspect-ratio and object-fit: cover; never fix a height in pixels on a content image.
  • Hero titles are fluid (--font-size-5xl clamp); other type is fixed in rem.
  • Text zoom to 200% and a 320px viewport must both reflow with no loss (1.4.4, 1.4.10).

Testing matrix

  • 390 x 844 (phone), 768 x 1024 (tablet), 1440 x 900 (desktop), light and dark.
  • Keyboard-only pass at each width; focus never hidden behind a sticky header.
  • Browser zoom 200% at 1440 and the pinch-zoom check on 390.

Accessibility

  • Do not lock orientation (1.3.4).
  • Reflow at 320 CSS pixels without two-dimensional scrolling (1.4.10).
  • Target size stays at least 24 x 24 CSS pixels at every breakpoint (2.5.8).
