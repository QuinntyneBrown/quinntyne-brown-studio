Theming

Three token tiers, light and dark themes, and how to add another.

WCAG 2.2 AAStatus: stable
  • Overview
  • How themes apply
  • Both themes
  • Adding a theme
  • Consuming tokens.json

Overview

Three tiers: primitives (--palette-*, --font-*) hold raw values; semantic tokens (--color-*, --text-*, --space-* ...) give them meaning and are the only tier themes override; component tokens (--btn-*, --field-*) scope a value to one component and always alias a semantic token.

How themes apply

  • Light is :root. Dark is [data-theme="dark"], and also applies automatically when the OS prefers dark unless the page sets data-theme="light".
  • Each theme sets color-scheme so native controls and scrollbars follow.
  • This site stores the visitor's choice in localStorage and honours ?theme=dark; press t to toggle.

Adding a theme

[data-theme="partner"] {
  --color-accent: var(--palette-olive-700);
  --color-fg-on-accent: var(--palette-white);
  --color-brand: var(--palette-olive-500);
}
  • Override semantic tokens only; never edit a component class.
  • Add every new foreground/background pairing to contrast-pairs.json and run check_contrast.py until it exits 0.
  • Re-export tokens.json with tokens_to_json.py.

Consuming tokens.json

tokens/tokens.json is a DTCG export ($type, $value, aliases as {group.token}, theme overrides under $extensions). The Angular workspace mirrors the values in frontend/styles.css; tokens.css stays the source of truth.

Do and don't

  • Do reference var(--color-*) in component stylesheets.
  • Don't write a hex value, a named colour or a font stack in a component. The checker rejects raw colours.
  • Don't invent a token for a single use; scope it as a component token instead.

Accessibility

  • Both themes meet the same contrast pairs.
  • prefers-contrast: more and forced-colors adjustments live in the token layer.
  • Never rely on the theme alone to convey state.
