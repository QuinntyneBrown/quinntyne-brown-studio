Component &middot; Actions

Button

Buttons let people take an action: save, send, delete, open. One primary button per view tells them what matters most.

WCAG 2.2 AAStatus: stableNative <button>

Overview

Use a button when activating it changes something: it submits, creates, deletes, opens a dialog or starts a process. Use a link when it only takes the person somewhere. Use a menu when several actions share one trigger.

  • Primary is the one action the view exists for. Never two per view.
  • Secondary (the default look) is for every other action.
  • Ghost sits inside dense surfaces: toolbars, table rows, dialog headers.
  • Link looks like an underlined word but behaves like a button; used for low-emphasis actions such as "Clear filters".
  • Danger is for destructive actions and appears only after a confirmation step or inside a confirmation dialog.

Anatomy

  1. Leading icon (optional)1.25em square, inherits the label colour, aria-hidden.
  2. LabelVerb phrase in sentence case; it is the accessible name.
  3. ContainerHeight from --control-height-*, --radius-xs corners, 1px border, padding from the spacing scale.

Variants

Variants change emphasis, not meaning. Pick by how much attention the action deserves on this view.

Highest to lowest emphasis; danger is reserved for destructive confirmations.
HTML
<button class="btn btn--primary" type="button">Primary</button>
<button class="btn" type="button">Secondary</button>
<button class="btn btn--ghost" type="button">Ghost</button>
<button class="btn btn--link" type="button">Link</button>
<button class="btn btn--danger" type="button">Danger</button>

With icons and icon-only

Icon-only buttons carry aria-label; the icon itself is aria-hidden.

Sizes

Medium is the default. Small lives in tables, toolbars and photo tiles; large is for hero and auth screens where the button is the point.

Heights: --control-height-sm/md/lg.

States

Every variant has the same states. Pointer and focus states are forced with data-state so they can be reviewed without a mouse; real pages get them from :hover, :focus-visible and :active.

Both themes

  • Loading keeps the width, hides the label, shows a spinner, sets aria-busy="true" and ignores clicks. Use it for the action that was pressed, not the whole form.
  • Disabled uses the native attribute, drops to 45% opacity and is not focusable. Prefer leaving the button enabled and explaining the problem on activation when the reason is not obvious.
  • Pressed (toggle buttons) uses aria-pressed; see button group.

Responsive behaviour

  • Below --layout-breakpoint-md (768px) the primary action of a form or page header becomes full width (.btn--block); secondary actions stack beneath it.
  • In dialog footers buttons stay on one row and wrap when the row is too narrow; the primary stays last.
  • Medium and large buttons already exceed the 44px comfortable target; small (32px) is only used where the surrounding row is also a target and neighbours are 8px apart.
  • Labels never truncate; a label that wraps at 390px is too long. Shorten the verb phrase.

Theming

The button reads only semantic tokens, mapped into component tokens (--btn-bg, --btn-fg, --btn-border, --btn-bg-hover) that each variant overrides. The studio's primary button is ink (--color-accent); in the dark theme the accent flips to near-white and the label to near-black so the pair stays above 7:1. A second product re-skins buttons by overriding the component tokens, never the class. 

[data-theme="partner"] .btn--primary { --btn-bg: var(--color-brand); --btn-fg: var(--color-fg-inverse); }

Accessibility

Role and pattern

Native <button type="button"> (or type="submit" in a form). A link styled as a button is still an <a href>; never a <div> with a click handler.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the button in DOM order.
Enter, SpaceActivates the button.
EscNo effect on the button itself; offer a separate Cancel for long actions.

Focus

The shared ring (2px --color-focus-ring, 2px offset) appears on :focus-visible only. It is at least 3:1 against page and card surfaces.

Labelling

The visible label is the accessible name. Icon-only buttons set aria-label with the verb and object ("Edit session"). Loading buttons keep their name and add aria-busy; announce the result in a live region.

Motion

Background and border transition over --duration-fast; the active state moves 1px. The spinner keeps rotating under reduced motion because it is a status indicator.

Touch

Medium (44px) and large (52px) meet the 44px target; small (32px) meets the 24px minimum and is used only with 8px between neighbours.

Content

  • Labels are verb phrases in sentence case: "Create session", "Send invitation". Never "OK", "Submit" or "Click here".
  • Name the object when context does not: "Request prints", not "Request".
  • Destructive labels name the loss: "Delete 3 photos", not "Confirm".
  • Keep labels to three words where possible.
