Progress

A progress bar shows how far a process has got: photographs uploading, a print request sending. It is a native element with a visible label and a value.

WCAG 2.2 AAStatus: stableNative <progress>

Overview

Use progress when a task takes more than a second or two and its length is known (determinate) or merely ongoing (indeterminate). Use a spinner for a short wait with no measurable end, and a skeleton for content that is on its way. Steps in a multi-page flow use a stepper, not a progress bar.

  • Determinate has a value between 0 and max. Used per file in file upload.
  • Indeterminate omits value. The track is empty and the label says what is happening.
  • Danger (.progress--danger) shows a failed task at the point it stopped, with the reason beside it.

Anatomy

  1. LabelNames what is progressing, such as the file name. Programmatically attached with aria-label or a wrapping <label>.
  2. Value text (optional)A percentage or "3 of 6 photographs" next to the label. Visible, not only in the bar.
  3. Track and fillTrack in --color-bg-subtle-hover, fill in --color-brand or --color-danger-solid; 0.5rem high with fully round ends.

Variants

Fill colour shows status: brand for normal progress, danger for a failure. Completion is shown by a full bar and a text change, not a new colour.

Determinate

A native <progress> with max and value.
HTML
<label>Uploading IMG_2041.CR3
  <progress class="progress" max="100" value="62">62%</progress>
</label>

Indeterminate

No value attribute. Always pair it with words that say what is happening.

Danger

A failed task stays at the point it stopped. The reason and a Retry action sit beside it.

Complete

A full bar, with the label changed to the past tense.

Sizes

Progress has one height (0.5rem). Wider bars are made by widening the container, not the bar.

States

The bar is a read-only indicator, so it has no hover, focus or active styling.

  • Updating: change value at most every second to keep announcements calm.
  • Indeterminate has no fill; set aria-busy="true" on the region it concerns.
  • Failed switches to .progress--danger and adds text beside the bar; colour alone is not enough.
  • Disabled and hover do not apply.

Responsive behaviour

  • The bar is block-level and fills its container, so it works at any width.
  • In upload rows the name, size, status and bar stack at 390px: name and status on one line, bar below.
  • Do not hide the percentage or status on small screens; the bar alone is a poor reading at 390px.

Theming

Track and fill use --color-bg-subtle-hover and --color-brand, which both change with the theme: olive-600 on stone-100 in the light theme, olive-300 on stone-800 in the dark theme. The fill stays at least 3:1 against the track in both. Failure uses --color-danger-solid.

Accessibility

Role and pattern

Native <progress>, which exposes the progressbar role with its value and range to assistive technology. See the APG Meter pattern for the related read-only indicator; progress is for work in progress, meter is for a measurement.

Keyboard

KeyAction
TabNot focusable; progress is a read-only indicator.
Enter, SpaceNo effect. Cancel and retry are separate buttons.

Focus

Never focusable. Any action next to it (Cancel, Retry) is a button with its own focus ring.

Labelling

Always give the bar a name: wrap it in a <label> or set aria-label. Announce milestones, not every tick: put a polite live region on the summary ("3 of 6 photographs uploaded") and update it at most every few seconds, or on completion and failure. For indeterminate work set aria-busy="true" on the busy region.

Motion

Value changes are not animated. Indeterminate progress shows no moving fill, so it respects prefers-reduced-motion by default.

Touch

Not interactive. Cancel and Retry buttons beside it follow the button sizes.

Content

  • Label what is progressing: a file name, "Uploading 6 photographs", "Preparing your album".
  • Show a number when you have one: "62%", or "3 of 6 photographs".
  • Say what happened when it ends: "IMG_2043.CR3 uploaded" or "IMG_2046.CR3 failed. Retry."
  • Do not promise times you cannot keep; avoid "about 2 minutes left" unless it is measured.
