Form field

The form field is the wrapper every input sits in. It owns the label, the hint, the error message and the space between fields, so the control inside can stay simple.

WCAG 2.2 AAStatus: stableWrapper, not a control

Overview

Wrap every text field, textarea and select in a form field. Checkboxes, radios and switches carry their own label and are grouped with a fieldset instead; see checkbox and radio group. Fields are arranged by form layout.

  • Label sits above the control and is always visible; placeholders are not labels.
  • Hint explains the format or the consequence before the person types.
  • Error replaces nothing: it appears beneath the control and names the problem and how to fix it.

Anatomy

  1. Label<label for> tied to the control, 14px, always visible.
  2. ControlAny input that uses .input; keeps its own border, height and states.
  3. HintCaption text in muted foreground, linked by aria-describedby.
  4. ErrorCaption text in the danger foreground with the control's aria-invalid="true"; linked by aria-describedby.

Variants

The wrapper has one structure; what changes is which of the optional parts are present.

Label only

Use when the label alone is enough.
HTML
<div class="field">
  <label class="field__label" for="phone">Phone</label>
  <input class="input" id="phone" type="tel" autocomplete="tel">
</div>

With hint

Name and city, for travel time.
The hint is read after the label and value.

With error

Enter a date that exists, such as 28 February.
The error is text, not just a red border.

Optional marking

Mark the exception. When most fields are required, label the optional ones; otherwise label the required ones.

Sizes

The wrapper has no size; control size is set on the input with <code>.input--sm</code> or <code>.input--lg</code>.

States

The wrapper changes with the control it holds. The same label and hint structure supports every state.

  • Required is stated in words ("required" or "(optional)" in the label) and by the native required attribute. An asterisk alone is not enough.
  • Error and hint together: both stay; the error is announced first because it is listed first in aria-describedby.
  • Busy: while a field validates on the server, set aria-busy="true" on the wrapper and keep the control editable.

Responsive behaviour

  • Fields take the width of their column. Below 768px every field is full width; above, two-column layouts come from form layout, never from the field.
  • The label never sits beside the control: stacking keeps the label readable at 390px and at 200% zoom.
  • Hints and errors wrap and are never truncated.

Theming

The wrapper reads --color-fg-default for labels, --color-fg-muted for hints and --color-danger-fg for errors. All three pass 4.5:1 on the canvas and on cards in both themes, so a field can sit on either surface.

Accessibility

Role and pattern

Native <label for> plus aria-describedby. No ARIA role is added; the control keeps its native role. The error uses aria-invalid="true" on the control.

Keyboard

KeyAction
Tab / Shift+TabMoves into and out of the control; the label and messages are not tab stops.
Click or tap the labelMoves focus to the control and, for checkable inputs, toggles it.

Focus

Focus belongs to the control, not the wrapper: the control shows the shared ring and a border in --color-focus-ring. After a failed submit, focus moves to the error summary, whose links move focus to the first invalid control.

Labelling

Every control has a visible <label> with matching for and id. Hints and errors have their own ids and are listed in aria-describedby. Errors are not removed on blur until corrected, and are never the only cue: they pair text with the red border.

Motion

Errors appear without animation. Nothing else moves, so there is nothing to reduce.

Touch

The label is part of the target for checkable inputs and at least 44px tall. Controls themselves are 44px (--control-height-md); the gap between fields is --space-5 (24px).

Content

  • Labels are short noun phrases in sentence case: "Session date", "Client email". No trailing colon.
  • Hints say what to enter or what happens next, not what the label already says.
  • Errors say what is wrong and how to fix it: "Enter a date that exists, such as 28 February." Never "Invalid input".
  • Do not use placeholder text for anything required to understand the field.

Code

<div class="field">
  <label class="field__label" for="email">Client email</label>
  <input class="input" id="email" type="email" autocomplete="email"
         aria-invalid="true" aria-describedby="email-hint email-err">
  <span class="field__hint" id="email-hint">We send the gallery link here.</span>
  <span class="field__error" id="email-err">Enter an email address such as name@example.com.</span>
</div>
