Component &middot; Feedback

Inline message

An inline message is the line of text under a field that says how to fill it in, what went wrong, or that it worked. It is tied to the field by code as well as by position.

WCAG 2.2 AAStatus: stableLinked with aria-describedby

Overview

Use an inline message for feedback about one control. For a message about the whole form or page use an alert; for a passing confirmation use a toast. Inline messages are normally rendered by form field, which sets up the labelling, but the same classes are used wherever a short note belongs to a nearby element.

  • Hint (.field__hint) explains the format or limit before the person types: "We only use this to reply to your enquiry."
  • Error (.field__error or .inline-error) says what is wrong and how to fix it. It replaces nothing: the hint stays.
  • Success confirms a value was accepted, for example a discount code applied. It uses the hint style with a leading check icon until a dedicated success class exists.

Validation timing is covered in forms: validate on blur, re-validate on input once a field has been marked invalid.

Anatomy

  1. ControlThe field the message belongs to. It carries aria-describedby listing the message ids, and aria-invalid="true" for errors.
  2. HintMuted caption text, always visible, under the control.
  3. ErrorCaption text in --color-danger-fg, shown below the hint, with a plain-words fix. Optional leading icon so colour is not the only cue.

Variants

Messages sit directly under the control, --space-1 below it, in the caption size.

Hint

Persistent guidance, muted.
HTML
<label class="field">
  <span class="field__label">Phone</span>
  <input class="input" type="tel" aria-describedby="phone-hint">
  <span class="field__hint" id="phone-hint">Optional. For same-day changes only.</span>
</label>

Error

Danger text plus an icon; the input border also turns to the danger colour via aria-invalid.
HTML
<input class="input" aria-invalid="true" aria-describedby="date-error">
<span class="field__error" id="date-error">Choose a date that exists, like 28 February.</span>

Success

Success is announced with a leading check icon and words.

Standalone error

Choose at least one photograph before requesting prints.

.inline-error for a message that is not tied to a single input, for example above a selection. Use role="alert" when it appears after an action.

Sizes

Inline messages use the caption size, one step below body, and do not have size variants.

States

Inline messages are static text; their states belong to the field they describe. The matrix shows how each message type looks beside a field in its main states.

Error

Both themes

  • Appearing: an error is inserted without animation and announced because the control's aria-describedby and aria-invalid change; also add the error to the form's error summary on submit.
  • Resolved: remove the error when the value becomes valid; keep the hint.
  • Loading and disabled do not apply to the message.

Responsive behaviour

  • Messages wrap under the control at its width; they never truncate.
  • At 390px keep errors to one or two lines. Longer guidance goes in the hint or a help link.
  • Do not float messages beside the control on wide screens: the message remains below so screen magnifier users find it next to the field.

Theming

Hints use --color-fg-muted, which reaches at least 4.5:1 on the surface in both themes. Errors use --color-danger-fg, a lighter red in the dark theme so contrast is preserved. The invalid border uses --color-danger-solid.

Accessibility

Role and pattern

Not a widget. The message is associated with its control through aria-describedby (WAI Forms tutorial, "Instructions" and "Validating input"). Errors also set aria-invalid="true" on the control.

Keyboard

KeyAction
Tab / Shift+TabMoves to the control; the screen reader reads its label, then its description (the hint and error).

Focus

Messages are not focusable. On a failed submit, move focus to the first invalid control or to an error summary that links to each one.

Labelling

List the ids of the hint and the error in the control's aria-describedby, hint first. Use an icon plus words for errors and success so colour is never the only signal (WCAG 1.4.1). Do not put role="alert" on every field error; the summary and focus move announce them.

Contrast

Motion

No motion. Messages appear and disappear instantly.

Touch

Text only; nothing to tap. If a link appears inside a message, give it 24px of target height or inline spacing.

Content

  • Say how to fix it, not only what is wrong: "Enter a full email address, like anna@example.com."
  • Never use "invalid" or "required field" alone. Name the field's expectation.
  • Keep hints short and keep them visible; do not hide format guidance in a placeholder.
  • Sentence case, a full stop at the end, no blame.
  • Success messages say what was accepted: "Code applied: 25% off your quote."
