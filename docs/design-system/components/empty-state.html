Empty state

An empty state fills the space where content would be, says why it is empty, and offers the next step. It turns a dead end into a starting point.

WCAG 2.2 AAStatus: stableNot an error

Overview

Use an empty state when a list, table, grid or page has nothing to show. It is not an error: if the content failed to load, say so with an alert or an error page. See empty and error states.

  • First run: nothing has been created yet, so the action is to create something.
  • No results: filters or search matched nothing, so the action is to clear them.
  • Permission: the person may not see anything here; say who can.
  • Compact (.empty-state--compact): inside a card, table body or side panel, with less padding.

Anatomy

  1. SymbolA single decorative glyph in the serif face; aria-hidden. It is not an illustration and carries no meaning.
  2. TitleA heading (h2 by default) naming the state. Use the level that fits the page outline.
  3. ExplanationOne sentence, muted, up to 27rem wide: why it is empty and what happens next.
  4. ActionOne primary button (or link), optionally with a secondary link. Container: dashed border on the sunken surface.

Variants

Pick the variant by cause. The cause decides the words and the action.

An empty state is static and has no states of its own. The one decision is whether it is the whole content or sits where content will later appear.

  • Loading: do not show the empty state while data is loading. Show a skeleton first.
  • Filled: when content arrives the empty state is removed from the DOM.
  • Hover, focus and disabled belong to the action button, not the container.

Responsive behaviour

  • The explanation is capped at 27rem and centred; the container fills its parent at every width.
  • Below 768px the vertical padding is reduced by one step so the action stays on the first screen.
  • At 390px the primary button can go full width (.btn--block) when it is the only action.
  • Never show an empty state and a populated list at the same time.

Theming

The container uses the sunken surface (--color-bg-surface-sunken) with a dashed strong border, so it reads as a place waiting for content in both themes. The glyph and explanation use --color-fg-muted; the title uses the default foreground.

Accessibility

Role and pattern

Static content. It contains a heading and optionally a button or link, so it takes part in the page outline. There is no ARIA role. When the state appears as the result of a filter or search, announce the change in a polite live region ("No photographs match").

Keyboard

KeyAction
Tab / Shift+TabReaches the action button or link, if any.
Enter, SpaceActivates the button (Enter only for a link).

Focus

Focus is not moved to the empty state. After a filter or search that causes it, leave focus on the control the person used.

Labelling

The title is the heading. The decorative glyph is aria-hidden="true". Use h2 unless the page outline needs another level; do not skip levels.

Contrast

Title on sunken surface
Explanation on sunken surface
Dashed border on page

Motion

No motion.

Touch

The action button is medium (44px). Place it 24px or more from other targets.

Content

  • Title states the fact: "No sessions yet", "No photographs match". Sentence case.
  • Explanation says why and what happens next, in one sentence.
  • The action is a verb phrase naming the object: "Add a session", "Clear filters". One primary action only.
  • Never blame: not "You have no sessions". Never cute: no jokes about missing photographs.
