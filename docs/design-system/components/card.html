Card

A card groups the information and actions about one thing, such as a session, an album or a print request, on a bordered surface.

WCAG 2.2 AAStatus: stableContainer <article> / <div>

Overview

Use a card when a block of content is one item among several, or stands apart from the page. Do not use a card to wrap an entire page, and do not nest a card inside a card; separate sections inside a card with a divider or the footer rule instead.

  • Default: white surface, hairline border, square corners.
  • Soft (.card--soft): a tinted surface with no border, for supporting content like the contact details beside a form.
  • Interactive (.card--interactive): lifts on hover. The card is not the control: it contains one real link or button, which is the only focus stop.
  • Selected (.card--selected): brand border and tint, for a card chosen from a set (a package, a print size).
  • With header and footer: .card__title at the top and a ruled .card__footer for actions.

A card holding one photo is a photo tile; a card for a blog post is a blog card.

Anatomy

  1. Title.card__title: serif heading; a link when the card goes somewhere.
  2. BodyFree content: text, a description list, media.
  3. Footer (optional).card__footer: hairline rule above actions or meta; no second border around it.

Variants

Choose by role: plain for content, soft for aside content, interactive for navigable items, selected for choices.

Sizes

A card takes the width of its container and the height of its content. Padding is fixed at <code>--space-6</code> (24px).

States

The default card is static. Interactive cards show hover and focus (on the link inside). Selected is a separate variant.

  • Hover only changes interactive cards (shadow); the other variants do not react because they are not controls.
  • Focus shows on the link or button inside, using the shared ring; the card has no tab stop of its own.
  • Selected is announced by the real input inside (checked); the tint repeats it for sighted users but never replaces it.
  • Loading: replace the body with skeleton lines and set aria-busy="true" on the card's grid.

Responsive behaviour

  • A card fills its column. In a .grid--3 (see layout) cards stack to one column on phones, three across at 768px.
  • Padding does not shrink on small screens; cards narrower than about 280px should stack their footer actions.
  • Card footers use a wrapping .cluster so two buttons never overflow.
  • Text wraps; titles do not truncate. If a title can be very long, clamp it to two lines and keep the full text in the link's accessible name.

Theming

A card is --color-bg-surface with --color-border-default. Soft uses --color-bg-subtle; selected uses --color-accent-subtle and --color-brand. All four swap in the dark theme; hover uses the shadow token, which is low-contrast on dark, so the border does not change.

Accessibility

Role and pattern

A card is not an ARIA widget. It is an <article> (self-contained item) or a plain <div> with a heading. A clickable card has exactly one link or button; if the whole card should be clickable, stretch that link's hit area over the card with CSS instead of making the card itself interactive or nesting links.

Keyboard

KeyAction
Tab / Shift+TabMoves to the link or buttons inside the card, in DOM order.
EnterFollows the card's link or activates the focused button.
SpaceSelectable cards: toggles the radio or checkbox inside.

Focus

Only the controls inside the card are focusable; they show the shared ring (2px --color-focus-ring, 2px offset). A selectable card keeps its radio or checkbox visible, so the input's own ring is the focus indicator.

Labelling

Give the card a heading (.card__title is a heading element) so it is findable in the outline. The link text names the destination ("Wedding session"); if several cards share link text, add a visually hidden suffix. Do not put role="button" or tabindex on the card.

Motion

Hover changes box-shadow over --duration-base. Under prefers-reduced-motion the transition is zeroed by the motion tokens and the shadow appears instantly.

Touch

The card's one control meets the 44px target (buttons) or sits in a 24px-minimum text link. Cards have 16px or more between them in a grid.

Content

  • Titles are the thing's name, not a label: "Wedding session", "Print request".
  • Body is one or two short lines; put detail on the destination page.
  • Footer actions are verbs: "Edit", "Review request". At most two.
  • Do not repeat the title in the body.
  • Use the same fields in the same order on every card in a set.
