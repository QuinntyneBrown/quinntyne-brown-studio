Switch

A switch turns one setting on or off, and the change takes effect straight away without a save step.

WCAG 2.2 AAStatus: stableCheckbox with role="switch"

Overview

Use a switch for a setting whose state is applied the moment it changes: "Gallery is public", "Email reminders". If the choice is submitted later with a form, use a checkbox. If there are more than two states, use a radio group. The label names the setting, never the action.

  • Label on the right is the default; the track sits at the start so a column of switches aligns.
  • With description adds a muted line saying what turning it on does.

Anatomy

  1. Track2.75rem by 1.5rem pill with a 1px border; fills with --color-accent when on.
  2. ThumbA circle that moves 1.25rem; changes colour as well as position so state is not shown by position alone.
  3. LabelStates the setting. Inside the same label so it is the accessible name and part of the target.

Variants

Switches are always a single control with a label. Group several under a heading, not a fieldset legend, when they are independent settings.

With description

The description is tied with aria-describedby.

Settings list

One label per switch; each is its own tab stop.

Sizes

One size: a 2.75rem by 1.5rem track in a 44px row. A larger track would crowd form rows; use the same size in tables and settings.

States

The native checkbox provides on, off, focus and disabled; hover and focus are forced with data-state for review.

Switch
With label

Both themes

  • Busy: while the change saves, keep the switch in its new position, set aria-busy="true" on the label and announce the result in a live region. If the save fails, return it to its previous state and say why in an inline message.
  • Disabled switches are dimmed to 45% and skipped; give the reason in the description.
  • Error is never shown on the switch itself; a failed change reverts and explains.

Responsive behaviour

  • Switches keep their size at every width. In a settings list the label wraps and the switch stays aligned to the first line.
  • At 390px the switch may sit at the end of the row (justify-content: space-between on the container) if the label is long; the order in the DOM does not change.
  • Never put a switch inside a table row without a row label that names the setting.

Theming

The track uses --color-bg-surface-sunken with a --color-border-strong border when off, and --color-accent when on. The thumb is --color-fg-muted off and --color-fg-on-accent on, so the off and on states differ by fill, thumb colour and position, not by one alone.

Accessibility

Role and pattern

WAI-ARIA APG Switch, built on a native checkbox: <input type="checkbox" role="switch">. The browser maps checked to aria-checked; do not add aria-checked by hand.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the switch.
SpaceToggles the switch.
EnterOptional: toggles (APG allows it); in a form it still submits when the native default applies.

Focus

The shared ring (2px --color-focus-ring, 2px offset) is drawn around the track on :focus-visible.

Labelling

The label states the setting in the present tense ("Gallery is public"), so the on and off states read naturally as "on" and "off". Never "Enable public gallery", which reads as an action. Descriptions use aria-describedby.

Motion

The thumb slides over --duration-fast. Under prefers-reduced-motion the duration is zero and the thumb jumps.

Touch

The row is 44px tall and the label is part of the target. The track itself is 44px by 24px.

Content

  • Label the setting, not the action: "Email reminders", not "Turn on email reminders".
  • Use the same noun in the label whether it is on or off.
  • Describe the consequence in the hint when it is not obvious: "Clients can save full-resolution photos."
  • Do not use "on" or "off" text inside the track; the position and colour carry the state.
