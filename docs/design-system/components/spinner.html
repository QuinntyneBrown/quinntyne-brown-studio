Spinner

A spinner says the system is working on something short and unmeasurable: loading a gallery, saving a session. It always has a text equivalent for screen readers.

Overview

Use a spinner for waits of roughly one to ten seconds where you cannot say how far along the work is, and for the busy state of a button. If you know the length, use progress. If you know the shape of the content that is coming, use a skeleton. If the wait is likely to exceed ten seconds, use progress with words. See feedback and loading.

  • Standalone centres in the area that is loading.
  • Inline with text sits beside a short phrase such as "Saving session…".
  • In a button replaces the label while the action runs; the button gets aria-busy="true".

Anatomy

  1. RingA circle with a transparent segment, drawn with a border in --color-border-strong; it rotates once every --duration-loop.
  2. Text equivalentVisually hidden text (or visible text beside it) that names what is loading. The wrapper has role="status".

Variants

One look, three sizes. Use the smallest size that is clearly visible next to the content it belongs to.

Standalone

Loading galleries
Centred in the loading region. The hidden text is announced politely.
HTML
<span class="spinner spinner--lg" role="status">
  <span class="visually-hidden">Loading galleries</span>
</span>

When the message is visible, the hidden text can be dropped, but keep role="status" on the container so the change is announced.

In a button

The button supplies its own spinner while aria-busy="true"; the label keeps its width and is hidden.

Sizes

Small is for inline text and buttons, medium is the default, large is for a loading region.

States

A spinner is either present or absent. It has no pointer or focus states, and it keeps turning under reduced motion because it is a status indicator.

  • Delay: show a spinner only after about 300ms, so quick loads do not flash it. Once shown, keep it for at least 500ms.
  • Finished: remove the spinner and move or announce the result; do not leave a hidden spinner in the DOM.
  • Hover, focus and disabled do not apply.

Responsive behaviour

  • The spinner is a fixed-size glyph and does not scale with the viewport.
  • In a loading region it centres horizontally and sits about a third of the way down, not at the bottom of a long page.
  • Inline spinners stay on the same line as their text at 390px; shorten the text rather than wrapping it.

Theming

The ring uses --color-border-strong, which stays at least 3:1 against the page and card surfaces in both themes. It does not use the accent colour, so it can sit inside primary buttons whose label colour changes between themes.

Accessibility

Role and pattern

A live region with role="status" and visually hidden text. There is no keyboard interaction. The related WAI-ARIA property for the region being updated is aria-busy="true".

Keyboard

KeyAction
TabNot focusable. Keep focus where it was; do not move it to the spinner.

Focus

Focus is never moved to a spinner. When loading ends, move focus only if the loaded content replaces the focused control; otherwise leave it.

Labelling

Name what is loading: "Loading galleries", "Saving session". A spinner with no text equivalent is invisible to screen reader users. Do not create more than one live spinner per region.

Motion

Rotates at --duration-loop. Under prefers-reduced-motion: reduce the spinner keeps turning because stopping it would remove the only signal that work is happening; do not add other loading animation to the page.

Touch

Not interactive. A spinner inside a button is sized to the 1rem small size and does not alter the button's 44px height.

Content

  • Name the thing: "Loading galleries", not "Loading".
  • Use the present participle with an ellipsis for visible text: "Saving session…".
  • Do not write "Please wait"; say what is happening.
  • When it ends, say what happened in a toast or on the page, not in the spinner.
