File upload

File upload lets a person add files by choosing them or dropping them, then shows each file’s progress so they know what arrived.

WCAG 2.2 AAStatus: stableNative <input type="file">

Overview

Use file upload for adding photographs to a session, a featured image to an article or documents to an inquiry. The native file input is always the control; the drop zone is an enhancement that adds drag-and-drop on top of it. Once files are chosen, show an upload row per file with progress and a result, and summarise the outcome in an alert.

  • Drop zone for batches: several photographs at a time.
  • Button only for a single file such as a logo.
  • File list with progress, success and failed rows beneath the zone.

Anatomy

  1. Drop zoneA dashed container; on drag it takes --color-brand-subtle. It is decoration; the input is the control.
  2. InstructionA heading and the accepted types and size limit, in text.
  3. Choose buttonA <label for> styled as a button that opens the system picker.
  4. File inputNative <input type="file">, visually hidden but focusable.

Variants

Start from the drop zone for batches and from the plain button for single files. Rows appear once a file has been chosen.

Drop zone

Drop photographs here

JPEG, PNG, WebP or AVIF. Up to 10 MB each.

Multiple files accepted. Types and size limit are in plain text, not only in accept.

Sizes

The drop zone fills its column and the rows are single-line; there is no size scale.

Dragging

  • Uploading: a row shows a <progress> with an accessible name and a text status ("Uploading 62%"). Progress is also announced politely at 25% steps.
  • Failed: the row's badge says "Failed", the bar turns to the danger colour and the action becomes "Retry". The reason is written in text beside it.
  • Rejected before upload: a wrong type or size is named in an alert above the zone ("anna-003.tiff is 18 MB; the limit is 10 MB").
  • Complete: a summary line in a polite live region ("3 photographs uploaded, 1 failed").

Responsive behaviour

  • The zone is full width and its padding drops to --space-5 at 390px. Dragging is rarely available on phones, so the choose button is always the primary path.
  • Rows collapse to two lines at narrow widths: name and size on the first, status and action on the second.
  • Never rely on drag and drop; every flow must work with the button and keyboard.

Theming

The zone border uses --color-brand and its fill --color-bg-surface-sunken; dragging switches the fill to --color-brand-subtle. Progress uses --color-brand and --color-danger-solid. All text pairs pass 4.5:1 in both themes.

Accessibility

Role and pattern

Native <input type="file"> is the control; the drop zone is a mouse and touch enhancement. Progress uses <progress> with an accessible name. Results are announced in a role="status" live region.

Keyboard

KeyAction
Tab / Shift+TabMoves to the choose button (the input) and then through row actions.
Enter, SpaceOn the focused choose button: opens the system file picker.
Enter, SpaceOn a row action: cancels, retries or removes that file.

Focus

The visually hidden input stays in the tab order and forwards focus styling to its label button (the shared ring appears on the button via :focus-within). After the picker closes, focus returns to the choose button. After removing a row, focus moves to the next row, or to the choose button if none remain.

Labelling

The input has a label (the button text, or a <label> for single files). Accepted types and the size limit are in visible text and in aria-describedby. Each progress bar is named "Upload progress for anna-001.jpg"; row buttons name the file they act on.

Motion

Progress advances in steps without easing. Under reduced motion the zone changes fill instantly on drag.

Touch

The choose button is 44px. Row actions use the small button (32px) with 8px spacing from the status badge.

Content

  • Heading and button say what is being added: "Drop photographs here", "Choose photographs".
  • State the accepted types and size limit in the zone, before an error can happen.
  • Errors name the file and the fix: "anna-003.tiff is 18 MB. Choose a file under 10 MB."
  • Never say "Upload failed" without a reason and a retry.
