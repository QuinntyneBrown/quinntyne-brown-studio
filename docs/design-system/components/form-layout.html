Form layout

Form layout arranges fields into sections, columns and an action bar, and gathers every error into a summary the person can act on.

WCAG 2.2 AAStatus: stableLayout primitives

Overview

Use form layout to compose form fields into a complete form: the session editor, the quote request, the sign-in form. It supplies the structure around the fields; it does not style the fields. The forms pattern covers when to validate and how to word errors.

  • Section groups related fields under a heading with a rule beneath it.
  • Columns place short fields side by side from 768px; they are single column below.
  • Action bar holds the primary action last, separated by a rule.
  • Error summary lists every problem with a link to each field and appears at the top after a failed submit.

Anatomy

  1. Section headingAn <h3> inside .form-section with a hairline rule beneath it.
  2. FieldsForm fields, spaced by --space-5.
  3. Columns.form-columns: one column below 768px, two from there.
  4. Action bar.form-actions: a rule above, buttons below; the primary is last.

Variants

A form is made of these pieces in this order: summary, sections, action bar. Not every form needs all of them.

Single column

The default. Short forms, phones and any form with long labels.
HTML
<form novalidate>
  <div class="field">…</div>
  <div class="form-actions">
    <button class="btn btn--primary" type="submit">Create session</button>
  </div>
</form>

Action bar

Primary first in reading order for left-to-right forms with three actions; with two actions put Cancel before Save.

Sizes

Form layout has no sizes. Widths come from the column; fields are never given fixed widths.

Fix 2 problems to save this session

  • Session date: enter a date that exists
  • Client email: enter an email address
  • Submitting: the pressed button shows its busy state and ignores clicks; the form is not otherwise disabled so the person can read it.
  • Invalid: the summary appears, each invalid field gets aria-invalid and a message, and focus moves to the summary.
  • Saved: an toast or alert confirms; the form stays so a mistake can be fixed.
  • Server error: an alert above the form says what failed and keeps every entered value.

Responsive behaviour

  • Below 768px .form-columns is one column and the action bar stacks with the primary button full width (.btn--block) first.
  • From 768px columns are two equal tracks with a --space-5 by --space-6 gap. Long fields (address, notes) span both.
  • The error summary is full width and sticks to the top of the form; fields it links to are scrolled below any sticky header by scroll-padding-top.

Theming

Section rules and the action bar divider use --color-border-default; section headings use --text-h3. The summary uses the danger alert colours (--color-danger-bg, --color-danger-border, --color-danger-fg) with a thick left border so it is not distinguishable by colour alone.

Accessibility

Role and pattern

A native <form novalidate> with custom messages. The error summary follows the GOV.UK pattern: role="alert" (or focus moved to it), a heading, and a list of links. Groups of related controls use <fieldset> with <legend>.

Keyboard

KeyAction
Tab / Shift+TabVisits fields in visual order; the summary links come first after an error.
EnterIn a text field, submits the form. On a summary link, moves focus to that field.
EscNothing in the form itself; in a dialog form it closes the dialog.

Focus

After a failed submit, focus moves to the summary heading (tabindex="-1"). Activating a summary link moves focus to the field, not just scrolls to it. After a successful save, focus moves to the confirmation or the next step.

Labelling

The form has an accessible name from its heading (aria-labelledby). The summary heading counts the problems ("Fix 2 problems to save this session"); each link text repeats the field label and the message. Required fields say so in words.

Motion

The summary appears without animation. Scrolling to a field uses the browser default smooth scroll only when reduced motion is not requested.

Touch

Every control and action is 44px tall. Buttons in the action bar are separated by --space-3 (12px) and stack on phones.

Content

  • Section headings are nouns: "Client", "Session", "Delivery".
  • The summary heading says how many problems and what the person is trying to do: "Fix 2 problems to save this session".
  • Each summary link reads like its inline message: field name, then the fix.
  • The primary action names the outcome: "Save session", "Send request".

  <div class="error-summary" role="alert" tabindex="-1" aria-labelledby="summary-title">
    <h2 id="summary-title">Fix 2 problems to save this session</h2>

  </div>

    <h3>Client</h3>
    <div class="form-columns">…fields…</div>
  </section>
  <div class="form-actions">
    <button class="btn" type="button">Cancel</button>

  </div>
