Sidebar

The sidebar is the admin workspace's table of contents: every area of the studio, grouped, with the current one marked.

WCAG 2.2 AAStatus: stableLandmark <aside> + <nav>

Overview

Use the sidebar in the admin app, where there are more than seven destinations and people move between them all day. For a public site with a handful of pages use the top bar instead. Inside one area, switch views with tabs, not more sidebar links.

  • Grouped: destinations sit under quiet group labels (Workspace, Studio, Pricing, Marketing) so a long list can be scanned.
  • Current: the active destination has a tinted background and aria-current="page". Child pages (the session editor, the upload page) keep their parent highlighted.
  • Footer: links that leave the workspace ("View website") and the sign-out action sit at the bottom, separated from the destinations.
  • Compact (mobile): below 768px the sidebar is hidden and a menu button in the app bar opens it.

Anatomy

  1. BrandWordmark linking to the dashboard.
  2. Group label.sidebar__group: uppercase overline, not interactive, not a heading link.
  3. Link.sidebar__link: at least --control-height-sm tall, 14px text; the current one carries aria-current="page".
  4. Footer.sidebar__footer is pushed to the bottom with margin-top: auto.

The sidebar is one component with two content variations: how many groups it carries and whether links show a count.

Sizes

The sidebar has one width, <code>--layout-sidebar-width</code> (220px). Collapsed-to-icons is not part of this system.

A sidebar link has default, hover, focus and current. Hover and focus are forced with data-state; real pages use :hover and :focus-visible.

  • Current uses --color-brand-subtle as the background; the text stays --color-fg-default so contrast does not change.
  • Open (mobile): the app shell shows the sidebar as a full-height panel when the menu button has aria-expanded="true". Focus moves to the first link on open and returns to the button on close.
  • Hover on current keeps the current tint; hover never removes the current indicator.

Responsive behaviour

  • At 768px and wider the sidebar is a persistent 220px column at the left of the workspace, and the content fills the rest.
  • Below 768px (--layout-breakpoint-md) the sidebar is hidden and the app bar shows a Menu button (aria-expanded, aria-controls="sidebar") that reveals it as a full-height panel.
  • A long list scrolls inside the sidebar; the footer stays reachable by scrolling, not by shrinking the links.
  • Labels wrap onto a second line instead of truncating; the longest current label is "Preferred vendors".

Theming

The sidebar uses its own surface token, --color-bg-sidebar (a barely tinted off-white in light, a slightly darker surface in dark), so it separates from the page without a heavy border. Current and hover use --color-brand-subtle and --color-bg-subtle-hover; both flip with the theme.

Accessibility

Role and pattern

An <aside> (complementary landmark) wrapping a <nav>. Links are plain <a>. This follows the APG Navigation landmark example. Do not use role="menu": a sidebar is a list of links, not an application menu.

Keyboard

KeyAction
Tab / Shift+TabMoves through brand, links and footer actions in order.
EnterFollows the focused link.
EscMobile only: closes the open sidebar and returns focus to the Menu button.

Focus

Each link shows the shared focus ring (2px --color-focus-ring, 2px offset). On mobile, opening the sidebar moves focus to its first link and closing it restores focus to the Menu button.

Labelling

Give the landmark and its nav distinct names ("Studio workspace", "Workspace") when more than one is present. Group labels are text; if they should be announced as headings, make them <h2> with the same class. Counts need an aria-label such as "3 new".

Motion

No motion. If the mobile panel slides, use --duration-base and remove the slide under prefers-reduced-motion.

Touch

Links are 32px tall plus a 2px margin on desktop, which meets the 24px minimum. In the mobile panel raise the link height to 44px (--target-comfortable).

Content

  • Labels are nouns for the area, 1-3 words, sentence case: "Sessions", "Quote rates", "Print pricing".
  • Group labels name a theme, not a verb: Workspace, Studio, Pricing, Marketing.
  • Keep the same order and names on every admin page (WCAG 3.2.3).
  • Links that leave the workspace say so: "View website" with an external cue.
  • Counts show only what needs attention; hide the badge at zero.
