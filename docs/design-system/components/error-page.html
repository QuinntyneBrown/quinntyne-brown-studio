Error page

An error page replaces a whole screen when the page cannot be shown: not found, access denied, service unavailable, session expired. It says what happened in plain words and gives exactly one way forward.

Overview

Use an error page when the entire route cannot be rendered. Use an alert when only part of a page failed, an empty state when there is simply nothing to show, and an inline message for field errors. See empty and error states.

  • Not found (404): the address does not match a page, or the record was removed. The action goes somewhere familiar.
  • Access denied (403): the person is signed in without permission or not signed in. The action is to sign in with another account.
  • Service error (503, 500): the studio could not respond. The action is to try again, with a way back.
  • Session expired: sign-in timed out. The action returns to sign in and keeps their place.

The same markup is used in the admin app, the client site and the marketing site. Only the destination of the action and the words "overview", "your sessions" or "the studio" change.

Anatomy

  1. Code or glyphLarge serif code (404, 403, 503) or a glyph for session expiry. Decorative, aria-hidden; the heading carries the meaning.
  2. HeadingThe page's one h1, in a warm, plain voice. Sets the document title too.
  3. ExplanationOne sentence: what happened and what is safe. Muted text.
  4. ActionOne button to recover. A second "Try again" button is allowed only for service errors.

The four mock pages share one layout. In the app the heading is an h1; here it is shown as h2 so this page keeps one h1.

Sign in
  • Retrying: the button shows a spinner, sets aria-busy="true" and ignores clicks. On success navigate home; on failure announce "Still unavailable" in a status region.
  • Offline: same layout, with "You are offline" as the heading and no code; retry when the connection returns.
  • Keep the app shell (top bar and sidebar) where the session is still valid; for expired sessions and public pages use no shell.

Responsive behaviour

  • The column is 40rem wide, centred, with a large top margin that shrinks to --space-8 below 768px.
  • The heading wraps; at 390px it should stay within three lines. The code scales down one size.
  • The action is full width at 390px (.btn--block) so it is easy to reach with a thumb.

Theming

The code uses the serif face in --color-fg-muted so it recedes behind the heading. All other colours come from the surface tokens, so the page switches theme with the rest of the app. No illustration is used, so nothing needs a dark variant.

Accessibility

Role and pattern

A normal document landmark: the content is the page's <main> with one h1. It is not a dialog and not a live region. Serve the right HTTP status (404, 403, 503) as well so crawlers and monitoring agree with the page.

Keyboard

KeyAction
Tab / Shift+TabReaches the action(s) in order after the skip link and shell.
Enter, SpaceActivates a button (Enter only for a link).

Focus

On a client-side navigation to an error page, move focus to the h1 (give it tabindex="-1") so screen reader users hear the problem. On a full page load the browser handles it.

Labelling

The h1 sets the page title: "Page not found | Quinntyne Brown Studio". The code is aria-hidden; never rely on the number alone. State the status in words in the explanation.

Motion

No motion. The Try again button uses the standard button spinner.

Touch

The action is medium (44px) or full width at 390px, with at least 8px between the two buttons on service errors.

Content

  • Say what happened in plain words, then give one way forward. Never show stack traces or internal ids to visitors; for 500 errors include a short reference the person can quote.
  • The heading can have warmth ("A little off the beaten path.") but the explanation is always plain.
  • Access denied says what to do ("Sign in with the right account"), not who is at fault.
  • The action names its destination: "Back to overview", "Back to your sessions", "Back to the studio".
  • Sentence case, curly apostrophes, no exclamation marks.
