Table

Tables compare records across the same attributes: sessions, print prices, inquiries. They scan quickly, sort, select and act on rows, and scroll sideways on a phone rather than hiding data.

WCAG 2.2 AAStatus: stableNative <table>

Overview

Use a table when people compare several attributes of many records or act on rows (open, edit, select). Use a description list for the attributes of one record, a card for a browsable record with an image, and a photo tile grid for photographs.

  • Default is comfortable: used in the admin app for sessions, inquiries, rates and vendors.
  • Dense trims row padding for short reference data such as print prices.
  • Sortable column headers are buttons that set aria-sort.
  • Selectable adds a checkbox column and a selection bar with bulk actions.
  • With thumbnails pairs a .table__thumb preview with a file name for media lists.
  • Pagination sits below the table: see pagination and the data tables and lists pattern.

Anatomy

  1. CaptionNames the table and its sort order. Visible, or visually-hidden when a heading already does the job.
  2. Column headers<th scope="col">, overline type in --color-fg-muted. Sortable ones hold a button.
  3. Row actionsGhost small buttons in .table__actions, always the last column, with a visually hidden header.
  4. Status cellA badge: colour, never colour alone, plus the word.

Variants

Every variant is the same native table with a modifier or an extra column. Pick by task, not by taste.

  • Row hover uses --color-bg-subtle; it is a convenience, so every action stays reachable by keyboard.
  • Row selected uses aria-selected="true" on the row and a checked checkbox: colour is never the only cue. --color-accent-subtle fills the row.
  • Sorted shows an arrow after the header text from aria-sort; sorting is announced because the button name stays constant and the header carries the state.
  • Loading: skeleton rows, aria-busy="true", header and caption stay. Under reduced motion the shimmer stops.
  • Empty: a compact empty state in place of the table with the next step as a button.
  • Error: a danger alert with role="alert" and a Retry button.

Responsive behaviour

  • Strategy: scroll, do not hide. The table stays a table. .table-wrap scrolls on the x axis at every width; header cells do not wrap, so columns keep their natural width and the page itself never scrolls sideways (WCAG 1.4.10 exempts data tables).
  • At 390px the first column (the record name) should stay readable without scrolling, so put the identifying attribute first and keep the table to six columns or fewer. The scroll region has tabindex="0", role="region" and a label so keyboard users can pan it with the arrow keys.
  • Row actions stay in the last column and may be scrolled out of view. If the primary action must be reachable at 390px, make the first-column text a link to the detail page.
  • For three or fewer attributes and a phone-first flow, render a list of cards instead of a table. Do not switch the same data between two DOM structures with CSS alone.
  • Selection bars wrap beneath the toolbar at narrow widths; the count stays first.

Theming

The table reads only semantic tokens: borders from --color-border-default, header text from --color-fg-muted, hover from --color-bg-subtle and selection from --color-accent-subtle. Nothing needs overriding for dark mode. Status colours come from the badge. 

.table { --table-row-hover: var(--color-bg-subtle); }

Accessibility

Role and pattern

Native <table> with <caption>, <thead>, scope on headers. Sorting follows the APG sortable table: a button inside the <th> and aria-sort on the header. It is not an ARIA grid: cells are not navigated with arrow keys.

Keyboard

KeyAction
Tab / Shift+TabMoves through sort buttons, checkboxes, row actions and links in DOM order, then out of the table.
Enter, SpaceOn a sort button: sorts, toggling ascending and descending. On a checkbox: Space toggles. On a row action: activates it.
← →Pans the focused scroll region sideways.
EscNo effect; use Clear in the selection bar.

Focus

Every interactive cell shows the shared 2px ring. The scroll region is focusable and shows the ring too. After sorting, focus stays on the sort button; after bulk actions complete, focus returns to the selection bar's first control or the table caption if the bar disappears.

Labelling

The caption (or an aria-label on the region) names the table. Header cells use scope="col"; row headers use scope="row" when the first cell identifies the row. Empty header cells are never left empty: use visually-hidden text such as "Actions". Checkboxes name their row ("Select Wedding session"). A loading table sets aria-busy and a status message; an error uses role="alert".

Motion

Row hover has no transition. The skeleton shimmer is decorative and stops under prefers-reduced-motion; the busy state is conveyed by aria-busy and text.

Touch

Row action buttons are small (32px) with 8px between them, meeting the 24px minimum. Checkboxes are 20px native controls inside cells at least 44px tall in the comfortable density; in dense they sit inside a 24px+ row and keep 8px of clearance.

Content

  • Column headers are nouns in sentence case, one or two words: "Date and location", not "When and where is it".
  • Dates in tables use a short form ("17 Oct"); put the year in the caption or a group heading if it varies.
  • Money is right-aligned text with the currency in the header, not in each cell: "Price (CAD)".
  • Empty cells show an em dash in --color-fg-muted, never a blank, "N/A" or "null".
  • Row actions are verbs: Open, Edit, Archive. Name the row in the accessible name when needed: "Edit Wedding session".
  • Empty and error copy says what happened and what to do next. See empty and error states.
