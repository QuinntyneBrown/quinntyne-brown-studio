Line item

A line item is one product in a request or order: a photograph, its print size, a quantity field and the line price.

WCAG 2.2 AAStatus: stableRow with a field

Overview

Use a line item in the print request and review screens, where each photograph becomes a priced row. Use a table for read-only data, a cost summary for the totals beneath, and a card for a browsable product.

  • Four parts, left to right: image, description, quantity field, price.
  • On a phone the image and description sit on one row and the rest wrap below.
  • Items stack in a list; removing one is an action on the item, not on the list.

Anatomy

  1. Image88px crop of the photograph, with alt.
  2. DescriptionPhoto name (h3), then size and finish in muted ink.
  3. Quantity fieldA text field with a visible label, small size.
  4. Line priceQuantity times unit price, right of the field.

Variants

The row is the same; what varies is the content in the description and the state of the field.

Sizes

A line item has one size; the image column is fixed and the rest flexes.

  • Removed: remove the row and announce "Photo 05 removed" in a live region; offer Undo in a toast.
  • Image failed: show the photo tile fallback text instead of a broken image.

Responsive behaviour

  • From 768px the grid is image, description, field (8rem) and price (5rem). Below, it is two columns: image and description, with the field and price wrapping to the next row beneath the description.
  • On a 390px screen the quantity field keeps its full tap width; the price aligns under it.
  • The image keeps its aspect crop; the description wraps and never truncates.

Theming

Border from --color-border-default; text from default and muted foregrounds; the field uses the shared input tokens. Everything adapts with the theme.

Accessibility

Role and pattern

A list of articles, each with a form field. Native <label> and <input type="number">. Rows are not a table, so there are no row/column semantics to maintain. Group items in a <ul> or <section> labelled "Print request".

Keyboard

KeyAction
Tab / Shift+TabMoves to each quantity field and remove button.
↑ ↓Steps the quantity in a number input.
EnterCommits the field; activates a remove button.
EscNo effect.

Focus

The input shows the shared ring. After removing a row, move focus to the next row's field, or to the previous, or to the list heading if none remain.

Labelling

The label "Quantity" is visible. Because several fields share the label, the accessible name is extended with aria-describedby pointing at the photo name, or the label is written "Quantity for Photo 01" in a visually hidden span. Errors use aria-invalid and a message linked by aria-describedby.

Contrast

Name on surface
Size and finish on surface
Error text on surface
Field border on surface

Motion

No motion beyond the field's border transition.

Touch

The small field is 32px tall (meets 24px); on a phone use the default field (44px) with .input. Remove buttons are small ghost buttons with 8px clearance.

Content

  • Item names are "Photo 01" plus the file name if useful; never the internal id.
  • Descriptions read size, then finish, separated by a middle dot: "8 × 10 in · Fine art matte".
  • Quantity errors say what to enter: "Enter a quantity of 1 or more."
  • Remove is a verb with the object: "Remove Photo 05".
  • Prices include the currency symbol and cents.
