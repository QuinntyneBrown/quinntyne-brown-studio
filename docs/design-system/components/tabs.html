Tabs

Tabs switch between sibling views of the same thing without leaving the page. One view is visible at a time and the selected tab says which.

WCAG 2.2 AAStatus: stableAPG Tabs

Overview

Use tabs when the views are peers that answer the same question: the categories of a portfolio, or the Details, Photos and Print requests of one session. Do not use them for steps in a sequence (use a stepper), for page-to-page navigation (use the top bar or sidebar), or to hide required content.

  • Pill (.tabs) is the default: rounded, outlined tabs; the selected one fills with ink. It suits short sets such as the portfolio categories.
  • Underline (.tabs--underline) is quieter and sits directly above its panel with a rule beneath. Use it inside a page or dialog where the strip is part of the content.
  • Activation: this system uses automatic activation. Arrow keys move focus and show the panel together, because each panel is already in the page. If a panel loads data slowly, use manual activation (arrows move focus; Enter or Space selects).

If choosing a tab only filters a list on the same page, a set of chips or a button group with aria-pressed is more honest than tabs with no panel.

Anatomy

  1. Tab listrole="tablist" with an aria-label; a flex row that wraps.
  2. Tab<button role="tab">. The selected tab has aria-selected="true" and tabindex="0"; the others -1.
  3. Selected indicatorPill: filled ink. Underline: 2px bar in --color-accent.

Variants

Both variants have the same markup and behaviour; only the class on the tab list changes.

Underline

Views of one session in the admin app.

With a count

A badge in the label counts what the tab contains. Give it an aria-label.

Scrollable

When the strip is wider than its container it scrolls horizontally inside a wrapper rather than wrapping. Keep the selected tab scrolled into view.

Sizes

Tabs have one size: <code>--control-height-sm</code> (32px) with 12px text. Compact tabs are not defined.

States

Both variants share states. Hover and focus are forced with data-state; real pages use :hover and :focus-visible.

Both themes

  • Selected is exposed with aria-selected="true", never with a class alone. The pill is filled and the underline is a 2px bar, so selection is visible without colour.
  • Disabled tabs drop to 45% opacity and are skipped by Tab. Prefer hiding a tab that cannot apply, or keep it enabled and explain in its panel.
  • Empty panel: show an empty state inside the panel, not a disabled tab.

Responsive behaviour

  • The strip wraps onto a second row by default (flex-wrap). Prefer the scrollable variant for the underline style so the rule stays continuous.
  • At 390px an underline strip of three short labels fits on one line; four or more scrolls.
  • Panels stack beneath the strip at every width; there is no side-by-side layout.
  • The strip never turns into a select box. If it needs that, the set is probably too large for tabs.

Theming

Pill tabs use --color-bg-surface, --color-border-strong and fill the selected tab with --color-accent / --color-fg-on-accent, which invert in the dark theme. Underline tabs use --color-accent for the bar. No component tokens are needed.

Accessibility

Role and pattern

WAI-ARIA APG Tabs: role="tablist" containing role="tab" buttons, each with aria-controls pointing to a role="tabpanel" that is aria-labelledby its tab. Roving tabindex: the selected tab is 0, the rest -1. Activation is automatic.

Keyboard

KeyAction
TabMoves focus into the tab list (to the selected tab), then to the panel, then onwards.
→ / ←Moves to and selects the next / previous tab; wraps from last to first.
Home / EndMoves to and selects the first / last tab.
Enter, SpaceSelects the focused tab (needed only with manual activation).

Focus

The ring is the shared 2px --color-focus-ring with 2px offset. After selecting a tab the focus stays on it; Tab then moves into the panel. Give the panel tabindex="0" when it has no focusable content.

Labelling

The tab list has an aria-label naming what the tabs choose between ("Session", "Gallery category"). The tab's text is its name. Counts inside a tab need an aria-label on the count.

Motion

The indicator changes instantly; there is no sliding underline, so there is nothing to reduce. If a product adds a background transition, use --duration-fast.

Touch

Tabs are 32px tall, above the 24px minimum, with 8px between pill tabs. On touch-first screens add vertical padding to reach 44px (--target-comfortable).

Content

  • Labels are one or two nouns, sentence case: "Details", "Print requests". Keep every label under about 16 characters.
  • Name tabs for what is inside, not for what to do: "Photos", not "View photos".
  • Order from most to least used; the first tab is selected by default.
  • Do not repeat the tab name as the panel's heading; the heading adds context ("Photos from this session").
  • Keep the set to 2-6 tabs.
