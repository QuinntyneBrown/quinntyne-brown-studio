Button group

A button group keeps related buttons together as one unit, either as a row of peer actions or as a segmented control that switches a view.

WCAG 2.2 AAStatus: stableWraps <button>

Overview

Use a button group when two or more buttons belong to the same decision: the actions at the end of a form, a toolbar over a photo grid, or a switch between two views of the same data such as "Grid" and "List". If the buttons are unrelated, space them as individual buttons. If there are more than four actions, move the extras into a menu.

  • Standard is a gapped row of ordinary buttons. It adds spacing and wrapping, nothing else.
  • Segmented fuses the buttons into one bar and is for choosing exactly one option. The chosen segment reports aria-pressed="true".
  • For switching between whole pages of content, use tabs, not a segmented group.

Anatomy

  1. Group containerrole="group" with an aria-label that names the choice.
  2. SegmentA native button. Inner corners are square; only the outer ends are rounded with --radius-xs.
  3. DividerNeighbouring segments overlap by one hairline so the shared border is drawn once.

Variants

Choose standard when every button runs its own action; choose segmented when exactly one of the buttons is always selected.

Standard group

A gapped row. The primary action is last.
HTML
<div class="btn-group" role="group" aria-label="Session actions">
  <button class="btn" type="button">Cancel</button>
  <button class="btn" type="button">Save draft</button>
  <button class="btn btn--primary" type="button">Publish gallery</button>
</div>

Segmented

One segment is always pressed. Exactly one choice, never none.
HTML
<div class="btn-group btn-group--segmented" role="group" aria-label="Schedule view">
  <button class="btn" type="button" aria-pressed="true">Week</button>
  <button class="btn" type="button" aria-pressed="false">Month</button>
  <button class="btn" type="button" aria-pressed="false">Agenda</button>
</div>

Toolbar with icon-only segments

Icon-only segments still carry a specific aria-label.

Sizes

The group inherits the size of its buttons. Mix nothing: every button in a group shares one size.

Small 32px, medium 44px, large 52px: --control-height-sm/md/lg.

States

A group has no state of its own; each segment carries the button states plus aria-pressed. Hover, focus and active are forced with data-state for review.

Both themes

  • Pressed is shown by the shared pressed style and by aria-pressed; never rely on colour alone, so keep the visible label different per segment.
  • Disabled applies per segment. Disable the whole group by disabling every button, and say why nearby.

Responsive behaviour

  • Standard groups wrap onto a second row when they run out of width (flex-wrap: wrap); the primary stays last in reading order.
  • Segmented groups never wrap. Below 390px keep labels to one short word each, or switch to a select when there are more than four options.
  • In a page header the group aligns to the end on wide screens and fills the row below --layout-breakpoint-md (768px).

Theming

Segments read the same component tokens as button (--btn-bg, --btn-fg, --btn-border), so a group re-themes with its buttons. The shared hairline between segments uses the secondary border, which stays above 3:1 in both themes.

Accessibility

Role and pattern

A container with role="group" and an aria-label. A segmented group is a set of toggle buttons (WAI-ARIA APG Button, toggle variant): each segment is a <button> with aria-pressed. It is not a radio group or a tab list, and it does not use a roving tabindex.

Keyboard

KeyAction
Tab / Shift+TabMoves through every segment in DOM order; each is a tab stop.
Enter, SpaceActivates the focused segment. In a segmented group this makes it the pressed one and unpresses the rest.
EscNo effect.

Focus

The shared focus ring (2px --color-focus-ring, 2px offset) is drawn on the focused segment above its neighbours, so the ring is never clipped by an overlapping border.

Labelling

The group has an aria-label naming the decision ("Schedule view"), not the control type. Each segment's visible text is its name. State changes that update other content are announced through that content's live region, not through the group.

Motion

Background and border change over --duration-fast; nothing slides between segments, so there is no motion to reduce.

Touch

Medium segments are 44px tall and each is at least 44px wide because of horizontal padding. Small segments (32px) are used in toolbars where every neighbour is also a target.

Content

  • Use one-word, parallel labels: "Week", "Month", "Agenda". Never mix nouns and verbs.
  • Name the choice in the group label ("Schedule view"), and keep it out of the visible text.
  • Two to four segments. More than that belongs in a select.
  • Sentence case, no trailing punctuation.
