Divider

A divider is a thin rule that separates two groups of content. It is decoration plus a hint of structure, never information on its own.

WCAG 2.2 AAStatus: stableNative <hr>

Overview

Use a divider between unrelated groups on the same surface, such as the contact details and the map on the contact page. Prefer spacing and headings to rules: if the groups already have headings, a divider is redundant. Use a card footer rule for actions inside a card, and a table's own row borders for tables.

  • Horizontal (.divider): a full-width hairline with 32px above and below.
  • Vertical (.divider--vertical): a 1.5em line between inline items, for example "Quinntyne Brown | Sign out".
  • With label: not a separate component. Put a small heading or eyebrow after a horizontal divider, so the label is a real heading.

Anatomy

  1. RuleA 1px line in --color-border-default, with 32px of space above and below. It is drawn with a border, not a background, so it survives forced-colours mode.

Variants

Use the element that matches the meaning: <hr> for a thematic break, role="separator" for a purely visual one.

Sizes

A divider has one weight, a hairline (<code>--border-width-hairline</code>). Spacing is adjusted with margins, not by thickening the rule.

States

A divider is static. There is nothing to hover, focus or select.

  • A divider is never interactive and never carries state; if a rule needs to be dragged (a resizable panel), use a separator with role="separator", tabindex="0" and value attributes, which is a different component.

Responsive behaviour

  • Horizontal dividers stretch to their container at every width.
  • Reduce the 32px vertical margin to 16px in dense panels with an inline margin override.
  • Vertical dividers sit inline and wrap with their items; hide them when items stack on narrow screens.
  • Never use a divider to separate stacked list rows; use the row's own bottom border.

Theming

The rule is --color-border-default, which is a light stone in the light theme and a dark stone in the dark theme. It is intentionally low contrast.

Accessibility

Role and pattern

A <hr> is exposed as a separator (a thematic break). For a visual-only rule use role="separator" or aria-hidden="true" on a non-semantic element. See the APG Window Splitter for the interactive separator, which this is not.

Keyboard

KeyAction
TabA divider is never in the tab order.

Focus

Not focusable. A rule that needs focus is a splitter and uses the shared focus ring on that element.

Labelling

No label. If the break needs a name, use a heading after it. Do not use a divider to give structure that headings, lists or landmarks should provide.

Contrast

Text above and below
Vertical item text

Motion

No motion.

Touch

Not a target. Keep at least 24px between the rule and the next interactive item.

Content

  • Dividers carry no text. A label is a heading.
  • Do not use one between every pair of items; use it where the topic changes.
  • Prefer spacing: if 32px of white space does the job, leave out the rule.
