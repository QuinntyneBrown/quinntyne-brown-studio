Textarea

A textarea takes free text longer than a line: a message to the studio, session notes, a caption or a print request comment.

WCAG 2.2 AAStatus: stableNative <textarea>

Overview

Use a textarea when the answer may run past one sentence. For a name, email or number use a text field. Wrap it in a form field so it has a label, hint and error. It shares the .input look with every other text control, and adds vertical resizing and a minimum of three rows.

  • Fixed rows for short notes: set rows to the expected length.
  • With counter when the content has a limit, such as a caption or a gallery description.
  • Auto-grow in editors that expand as the person writes, up to a maximum height.

Anatomy

  1. LabelVisible, above the control, tied with for.
  2. Text areaSame border, radius and fill as text field; minimum three rows.
  3. Resize handleVertical only (resize: vertical); never horizontal.
  4. Counter or hintCaption below, linked with aria-describedby.

Variants

The control is the same; the difference is in the surrounding hint and the way it grows.

Default

Three rows is the minimum visible height.
HTML
<label class="field__label" for="note">Note for the photographer</label>
<textarea class="input" id="note" rows="3"></textarea>

With character counter

46 of 200 characters
The counter is plain text, not live-announced on every key; see accessibility.

Large editing area

Markdown is supported.
Use more rows for long-form content such as blog posts.

Sizes

Textarea height is set with the <code>rows</code> attribute and the person&rsquo;s resize, not by a size scale. Typography matches the medium text field.

States

The same states as a text field. Hover and focus are forced with data-state for review.

VariantDefaultHoverFocusInvalidDisabledRead-only
Empty
Filled

Both themes

  • Invalid shows the red border and a visible message in the form field.
  • Counter over limit turns the counter text to --color-danger-fg and sets aria-invalid; hard-stopping with maxlength is still preferred where truncating is safe.
  • Read-only keeps the text selectable and focusable; disabled does neither.

Responsive behaviour

  • Full width of the column at every size. Rows stay the same, so the visible height does not collapse on phones.
  • The resize handle is hidden on coarse pointers by the browser; do not rely on it for reaching the content.
  • Long words wrap rather than scroll horizontally.

Theming

Colours match the text field: --color-bg-surface, --color-border-strong, --color-fg-default. The dark theme inherits through the same tokens; the resize grip is drawn by the browser from color-scheme.

Accessibility

Role and pattern

Native <textarea> (WAI-ARIA APG Textbox, multi-line). No ARIA role is needed.

Keyboard

KeyAction
Tab / Shift+TabMoves focus into and out of the field. Tab never inserts a tab character.
EnterInserts a new line; it does not submit the form.
Ctrl/Cmd+EnterOptional: submit, only when the screen says so beside the field.

Focus

Border becomes --color-focus-ring with the shared 2px ring on :focus-visible. Focus stays in the field while the counter updates.

Labelling

A visible <label for>. The counter is referenced by aria-describedby and updated on a short debounce into a polite live region only when the limit is near or exceeded, so screen readers are not interrupted on every key press.

Contrast

Text on field
Border on surface
Counter on canvas
Over-limit counter on surface
Focus ring on surface

Motion

Auto-grow changes height instantly; there is no animated resize.

Touch

The first row is 44px or taller and the whole box is a target. Keep 8px or more between the box and neighbouring buttons.

Content

  • Label as a noun: "Message", "Note for the photographer". Hints say how it will be used.
  • Give an example in the hint when the content has structure ("Include the venue, date and number of guests").
  • State the limit before the person reaches it.
  • Do not pre-fill with placeholder prose.
