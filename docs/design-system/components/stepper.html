Stepper

A stepper shows the steps of a process in order and where the person is in it: the quote journey, a print request, how a session works.

WCAG 2.2 AAStatus: stableOrdered list

Overview

Use a stepper to explain or track a short sequence of three to five steps. For long forms with sections use form layout; for navigating between peer views use tabs; for a hierarchy use a breadcrumb.

  • Explaining: all steps are equal and none is current ("How it works").
  • Tracking: one step is current (aria-current="step"); completed steps say so in text.
  • Number is generated from the list, so reordering never leaves wrong figures.

Anatomy

  1. Rule and numberA top rule, thick when current, and a serif numeral generated by a CSS counter.
  2. Titleh3 in the h3 type style; a short verb phrase.
  3. DescriptionOne sentence in muted ink explaining what happens in the step.

Variants

The stepper is an ordered list of up to five steps. Choose horizontal for desktop explainers; it stacks to vertical on phones automatically.

Tracking, step 1 current

  1. Tell us about the day

    Pick a service and a date, and share a few details.

  2. Review your quote

    See the estimate update as you change options.

  3. Confirm with the studio

    We reply within two working days to lock in the date.

The current step's rule is thick and ink-coloured.

<ol class="steps">
  <li class="step" aria-current="step"><h3>Tell us about the day</h3><p>Pick a service and a date.</p></li>
  <li class="step"><h3>Review your quote</h3><p>…</p></li>
</ol>

Sizes

The stepper has one size; the number of steps sets the column width.

States

A step is upcoming, current or complete. Current is a real attribute; complete is stated in text beside the title.

  • Error: when a step needs attention, add a badge--error with "Needs attention" and link to the step.
  • Responsive: below 768px the steps stack in one column with the same rule and number.

Responsive behaviour

  • At 768px and wider, three steps sit side by side; below, they stack in order.
  • Five steps are too many for three columns: override grid-template-columns only in a layout wrapper, not by changing the component.
  • The numeral and rule move with the step so each remains self-contained when stacked.
  • Text never truncates; descriptions wrap.

Theming

Rule colour from --color-border-default; the current rule and the numeral use --color-accent and --color-brand, which swap in the dark theme. Description text uses --color-fg-muted.

Accessibility

Role and pattern

A native ordered list. The current step uses aria-current="step"; there is no tab role because steps are not interactive. If steps are links, wrap each title in an <a> and keep the list.

Keyboard

KeyAction
Tab / Shift+TabMoves through any step links in DOM order; plain steps are skipped.
EnterFollows a step link.
EscNo effect.

Focus

Steps take no focus unless they are links. When the person advances, move focus to the heading of the new section, not the stepper.

Labelling

The list reads "list, 3 items". The counter numeral is generated content; screen readers may read it, so do not repeat numbers in the title. The current step is announced as "current step". State completion in text.

Motion

No animation; step changes are instant.

Touch

Plain steps are not targets. Step links should be at least 44px tall in the title row.

Content

  • Titles are short verb phrases in sentence case: "Review your quote".
  • Descriptions are one sentence; no more than 20 words.
  • Three to five steps. If you need more, group them.
  • Do not number the titles; the component does it.
