Layout primitives

Five small classes arrange everything on a page: container, grid, stack, cluster and split. Pages compose them; components never set their own outer margins.

Overview

Layout primitives place things; they draw nothing. Reach for them before writing a one-off flex or grid rule. Each one owns exactly one decision: how wide the content may be, how items line up in columns, how blocks stack, how inline items wrap, or how a main column pairs with an aside. Spacing values come from the spacing tokens and breakpoints from layout and responsive.

  • Container (.container): centres content up to 1360px with side margins from --layout-margin.
  • Grid (.grid with --2, --3, --4): equal columns that collapse to one on phones; gutters from --layout-gutter.
  • Stack (.stack): vertical rhythm. Sets the gap between children, --stack-gap (20px by default).
  • Cluster (.cluster): inline items that wrap, such as buttons, chips or meta. Gap --cluster-gap (12px by default).
  • Split (.split): a main column and a narrower aside; stacks below 1100px.

Anatomy

  1. ContainerThe outer box: max width --layout-container-max, side margin --layout-margin, centred.
  2. GutterThe gap between columns: --layout-gutter (16px, 24px at 768px, 32px at 1100px).
  3. ColumnA grid track. The count is 4, 8 or 12 as the viewport grows (--layout-columns); named grids use 1, 2, 3 or 4 equal tracks.

Sizes

Layout primitives have no sizes; their dimensions are set by container width, breakpoints and spacing tokens.

States

Primitives are static and have no interaction states. Their only variation is the viewport, covered in Responsive behaviour. The frame below shows the default container.

  • A primitive never has hover, focus or selected states; the content inside does.
  • Wrap a grid's children in the elements that make sense (article, li); the grid does not require a particular tag.

Responsive behaviour

  • Breakpoints: 480px (--layout-breakpoint-sm), 768px (-md), 1100px (-lg), 1280px (-xl), 1500px (-2xl). Design mobile first and add columns upward.
  • Columns: 4 under 768px, 8 from 768px, 12 from 1100px. Gutter: 16, 24, 32px. Margin: 16, 32, 48px.
  • Grid: grid--2 and grid--3 go to 2 and 3 columns at 768px; grid--4 goes to 2 at 480px and 4 at 1100px.
  • Split: stacked below 1100px, with the aside after the main content so reading order is preserved.
  • Container holds at 1360px; content wider than that is centred with side space, not stretched.
  • Test at 390, 768 and 1440 CSS pixels, and at 320px with 400% zoom for reflow.

Theming

Layout primitives draw nothing, so they have no colour and nothing to theme. The cards in the examples use --color-bg-subtle and swap with the theme.

Accessibility

Role and pattern

No role. Layout primitives are generic containers; the semantic elements inside them (headings, lists, landmarks) carry the meaning. Never use CSS grid or order to put content in a different reading order from the DOM.

Keyboard

KeyAction
TabFollows DOM order. Because the primitives never reorder items, the visual order is the tab order (WCAG 2.4.3).

Focus

Primitives are not focusable. Ensure the container's side margin and the grid gutter leave room for the focus ring (2px outline plus 2px offset) so it is never clipped by overflow: hidden.

Labelling

Not applicable. Landmarks (<main>, <nav>, <aside>) are placed inside the primitives, not given by them.

Motion

No motion; layout changes with the viewport and never animates.

Touch

Gutters of at least 16px keep adjacent targets apart; the 8px stack and cluster gaps used in dense rows still leave 24px target spacing with 44px controls.

Content

  • Do not describe layout in copy ("on the left", "below"); the order changes by viewport.
  • Keep line length near --layout-measure (65ch) for reading text, even inside a wide container.
  • Put the most important content first in the DOM; the aside follows.
  • Name layouts for what they hold in code comments, not for how they look.
