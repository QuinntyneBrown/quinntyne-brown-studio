Radio group

A radio group presents two to six options and lets the person choose exactly one, with every option visible.

WCAG 2.2 AAStatus: stableNative <input type="radio">

Overview

Use a radio group when one answer is required and the options fit on screen: delivery method, print finish, session length. For seven or more options use a select. For independent yes/no choices use checkboxes. For view switches inside a page use a segmented button group.

  • Vertical is the default and the easiest to scan.
  • Horizontal for two or three short options such as "Yes" and "No".
  • Card style for options with a description or price, such as print packages.

Anatomy

  1. LegendNames the question; it is read before each option.
  2. RadioNative control, 1.25rem, filled with --color-accent when chosen.
  3. LabelWraps the input; the whole row is at least 44px tall.

Variants

Every radio in a group shares one name. The wrapper decides how they are laid out.

Vertical

Delivery
One choice always stays selected once the group has a default.
HTML
<fieldset class="fieldset">
  <legend>Delivery</legend>
  <label class="check"><input type="radio" name="delivery" value="digital" checked>Digital download</label>
  <label class="check"><input type="radio" name="delivery" value="album">Printed album</label>
</fieldset>

Horizontal

Do you have a venue?
Short answers only; wrap to a column at narrow widths.

Card style

Print finish
Selected card takes the brand border and subtle fill.

Sizes

The control is a fixed 1.25rem (20px) inside a 44px row. Option text follows the surrounding type scale.

States

Hover and focus are forced with data-state; the browser sets checked, disabled and focus states on real pages.

Both themes
Both themes
  • Invalid applies to the group when none is chosen on submit. Set aria-invalid on the fieldset, show an error beneath the options and link it in the error summary.
  • No default is allowed only when the person must make an explicit choice (for example consent). Otherwise preselect the most common option.
  • Disabled options stay visible with a reason, so the choice can still be understood.

Responsive behaviour

  • Vertical groups are the same at every width. Horizontal groups wrap to a column when they do not fit, which usually happens below 480px.
  • Cards stack in one column; a two-column card grid is allowed from 768px when each card is under 20 characters wide.
  • Descriptions wrap and never truncate.

Theming

Radios use the native control with accent-color: var(--color-accent), so the chosen dot and ring follow the theme. Cards use --color-brand and --color-accent-subtle for the chosen state; the legend and labels read --color-fg-default.

Accessibility

Role and pattern

WAI-ARIA APG Radio Group, implemented natively: <fieldset> with <legend> and inputs sharing a name. No ARIA roles are needed, and none should be added to native inputs.

Keyboard

KeyAction
Tab / Shift+TabMoves focus into the group on the chosen radio (or the first if none) and out of it. The group is one tab stop.
↓ / →Moves to and chooses the next radio, wrapping from last to first.
↑ / ←Moves to and chooses the previous radio, wrapping.
SpaceChooses the focused radio if it is not already chosen.

Focus

Only the chosen radio is in the tab order; arrow keys move focus and selection together. The shared 2px ring shows on :focus-visible on the radio, and card style also outlines the card.

Labelling

The legend names the question ("Print finish") and each label names the answer. Descriptions are inside the label. If a visible legend would repeat a heading, use aria-labelledby on the fieldset pointing at that heading instead of hiding the legend.

Motion

The dot appears without animation; nothing to reduce.

Touch

Each row is at least 44px tall and the full width of its column, so the label is part of the target. Cards add padding on top of that.

Content

  • The legend is a question or a noun phrase: "Delivery", "Print finish".
  • Labels are parallel, short and distinct. Put the shared words in the legend.
  • Order options by likelihood, or logically (small to large).
  • Never use "Other" without a text field that appears when it is chosen.
